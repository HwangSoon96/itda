## 데이터와 사용자 흐름

- 프론트는 백엔드만 호출하며, 백엔드가 AI 서버 호출·저장·집계를 담당합니다.
- 원문 수정은 같은 메모를 재정리합니다. 이전 원문에 속한 사건·확정 상태·집계를 무효화하고 새 결과를 다시 확인합니다.
- 사건 확인은 최종 목록 전체를 저장합니다. 잘못 추출한 카드는 삭제하며 발생 여부를 별도로 선택하지 않습니다. 근거는 원문에서 선택하고 원문 변경과 사건 편집을 구분합니다.
- 질문은 `created_at`의 날짜가 요약 시작일~종료일 안에 있으면 포함합니다. 양 끝 날짜를 포함합니다.
- 경과·요약지·일정은 요약 기간 선택을 공유합니다. 서버가 반환한 실제 기간과 화면의 선택이 일치해야 합니다.
- 경과·요약지·PDF의 약 변경과 낙상은 별도 영역으로 표시합니다. 데이터는 `Summary.medications`, `Summary.falls`를 그대로 사용합니다.
- 저장·삭제 후 기록·질문 목록과 보고서 캐시를 갱신합니다. 요약은 데이터가 바뀌지 않았다면 같은 훅 안에서 요청과 결과를 재사용합니다.
- 메모 팝업은 열었던 화면으로 돌아갑니다. 지난 기록 목록과 PDF 출력 전 확인 흐름을 유지합니다.
- PDF는 프론트의 A4 인쇄 레이아웃과 브라우저 인쇄 기능으로 출력합니다. 서버 PDF 생성 API는 현재 사용하지 않습니다.

구현 위치는 [구조 문서](architecture.md), 통신 상세는 [API 계약](api-contract.md)을 참고합니다.
