# 개발 기준

백엔드 구조와 도구 선택을 정리합니다. API·계산 규칙의 결정은 팀 API 명세서 v3의 결정 목록(F·V·A·R 번호)을 따릅니다.

| 날짜 | 결정 | 이유 |
| --- | --- | --- |
| 2026-09-29 | FastAPI + SQLAlchemy 2.0 + SQLite + Pydantic 2 | 상세 개발 가이드 3장. 보호자 PC 한 대에서 파일 하나로 동작 |
| 2026-09-29 | 가이드의 `python -m venv` + `pip install` 대신 **uv**(`pyproject.toml` + `uv.lock`) | itda-ai가 이미 uv를 씀. lock 파일로 팀원·시연 PC의 버전이 같아지고, 가상환경을 켜지 않아도 `uv run`으로 실행 |
| 2026-09-29 | Python 3.12 고정 (`.python-version`) | itda-ai와 같은 버전. Ubuntu 24.04 기본 |
| 2026-09-29 | 가이드의 의존성에서 pandas 제외 | 통계 계산은 날짜 집합과 나눗셈이라 표준 라이브러리로 충분. 설치가 가벼워짐 |
| 2026-09-29 | 린트·포맷은 ruff | 도구 하나로 린트·포맷·import 정렬 |
| 2026-09-29 | 라우터는 루트 경로, `/api` 접두어는 미들웨어가 뗌 | 개발(vite 프록시)과 시연(static 제공) 모두 프론트 설정 그대로 동작 (명세 F18) |
| 2026-09-29 | DB 파일은 `ITDA_DB`로 바꿀 수 있음 | 발표 때 demo.db로 실행, 실제 기록과 분리 (명세 F17) |
| 2026-09-29 | 테이블은 시작할 때 `create_all`, 마이그레이션 도구 없음 | MVP 규모. 스키마를 바꾸면 itda.db를 지우고 다시 만듦 |
| 2026-09-29 | `app/services/dates.py`(시간 표현 → 날짜) 만들지 않음 | 사건 날짜 = 메모의 record_date (명세 F01, 기획팀 확인 필요) |
| 2026-09-30 | 증가 표시 기준선 비교를 float 대신 분수로 정확히 계산 | 식은 명세 그대로. float 반올림 때문에 딱 기준선인 값(기준 10/15, 이번 60/72 등)이 '증가'로 잘못 표시됐음. 프론트 샘플(mockApi.ts)은 float 그대로라 이 경계에서만 다를 수 있음 |
| 2026-09-30 | `/summary`·`/trends`의 `as_of`가 오늘 이후면 422 `future_date` | 프론트도 미래 기준일을 막음. `9999-12-31`은 주 계산에서 날짜가 넘쳐 500이 났음 |
| 2026-09-30 | 경로의 id는 1 ~ 2^63-1만 받음 (`errors.Id`), 밖이면 422 | SQLite INTEGER 범위를 넘는 id가 DB까지 가서 OverflowError로 500이 났음 |
| 2026-09-30 | DB 연결 풀을 쓰지 않음 (`NullPool`) | 동시 저장이 풀 크기(15)를 넘으면 AI를 기다리는 요청이 연결을 쥔 채 이벤트 루프가 막혀 서버 전체가 멈췄음 |
| 2026-09-29 | 데모는 `app/routers/demo.py` 대신 명령으로 demo.db를 만듦 | 버튼 한 번에 실제 기록을 지울 위험 제거 (명세 F17, 기획팀 확인 필요) |
